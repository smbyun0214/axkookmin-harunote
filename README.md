## 1. 바로 써 보기

### 가장 쉬운 방법: 배포된 사이트
1. 브라우저(Chrome, Safari 등)에서 https://axkookmin-harunote.vercel.app 을 엽니다.
2. 설치도 로그인도 필요 없습니다. 처음 열면 **샘플 할 일 100개**가 이미 들어 있어서 그래프를 바로 볼 수 있어요.

> 데이터는 **지금 쓰는 브라우저 안에만** 저장됩니다. 다른 기기·다른 브라우저에서는 보이지 않고, 이 사이트의 데이터는 다른 사람에게 보이지 않습니다.

### 내 컴퓨터에서 실행하기 (코드를 고쳐 볼 때)
macOS에 기본으로 들어 있는 `python3`만 있으면 됩니다.

**방법 A: 서버 시작 버튼 (가장 쉬움)**
1. Finder에서 이 폴더를 엽니다.
2. **`서버시작.command`** 파일을 더블클릭합니다.
3. 터미널 창이 열리고, 잠시 뒤 브라우저에 앱(`http://localhost:5001`)이 열립니다.
4. 끝낼 때는 그 터미널 창에서 `Ctrl + C`를 누르거나 창을 닫습니다.

> 처음 더블클릭할 때 "확인되지 않은 개발자" 경고가 나오면: 파일을 **오른쪽 클릭 → 열기 → 열기**를 누르세요. (한 번만 하면 됩니다)

**방법 B: 터미널에서 직접**
1. 터미널에서 이 폴더로 이동합니다.
2. 아래 명령을 실행합니다. (이 컴퓨터에서 앱을 보여주는 작은 서버를 켜는 명령입니다)
   ```bash
   python3 server.py
   ```
3. 브라우저 주소창에 `http://localhost:5001` 을 입력합니다.

> 💡 5000번이 아니라 5001번을 쓰는 이유: macOS의 "AirPlay 수신 모드"가 5000번을 이미 쓰고 있어서 충돌합니다.
> `server.py`는 브라우저가 옛 파일을 기억하지 않게 해서, 코드를 고친 뒤 새로고침하면 바로 반영됩니다.

## 2. 처음 10분 따라 하기

순서대로 눌러 보면 이 앱의 핵심(할 일 → 히스토리)을 모두 경험할 수 있습니다.

### ① 히스토리부터 구경하기
1. 왼쪽 메뉴에서 **히스토리**를 누릅니다.
2. 위쪽에 숫자 타일 3개, **진행 중인 브랜치** 카드, 아래에 **그래프**가 보입니다. (샘플 데이터 기준 진행 중인 할 일은 6개)
3. 그래프 맨 위 **"지금"** 줄에 진행 중인 할 일이 칩(알약 모양 버튼)으로 모여 있는지 확인하세요. 칩을 누르면 오른쪽 **선택한 기록**에 자세한 내용이 나옵니다.

### ② 할 일 추가하기
1. 왼쪽 메뉴에서 **할 일**을 누릅니다.
2. 맨 위 "새로운 할 일" 입력줄에 내용을 쓰고 **Enter**를 누릅니다. (날짜 칸은 기본으로 오늘)
3. **오늘** 목록에 새 할 일이 생깁니다.
4. 다시 **히스토리**로 가 보세요. 진행 중 브랜치가 하나 늘고, "지금" 줄에 새 칩이 생겼습니다. 그래프에서는 main 줄기에서 새 가지가 갈라져 나와요.

### ③ 할 일 열어서 꾸미기
1. 할 일 목록에서 방금 만든 할 일의 **제목**을 누릅니다. 창이 열립니다.
2. 왼쪽 아래의 **+ 체크리스트**를 누르고 항목을 적은 뒤 **Enter**를 누르면 다음 항목 칸이 생깁니다.
3. 오른쪽 위에서 **마감일·우선순위·반복**을 바꿔 봅니다.
4. **저장**을 누르면 "저장했어요 · 히스토리에 기록했어요"가 뜹니다.
5. 같은 할 일을 다시 열면 **오른쪽 아래 작은 그래프**에 방금 바꾼 내용이 기록으로 쌓여 있습니다. (예: `우선순위 보통 → 높음`)

### ④ 진행하고 완료하기
1. 할 일을 열어 체크리스트 항목에 체크하고 저장합니다. 기록에 `체크리스트 0/3 완료 → 1/3 완료`처럼 남습니다.
2. 목록에서 할 일 왼쪽 **동그라미**를 누르면 완료됩니다.
3. **히스토리**로 가 보세요. 그 할 일의 가지와 기록이 **완전히 사라졌습니다.** (히스토리에는 진행 중인 일만 남아요)
4. 완료한 할 일은 **할 일 → 완료됨**(눌러서 펼침)과 **하루 기록**에서 볼 수 있습니다.
5. 완료를 취소하려면 **완료됨** 목록에서 동그라미를 다시 누르세요. main에서 새 가지가 다시 생깁니다.

### ⑤ 일정 만들기
1. 왼쪽 메뉴에서 **캘린더**를 누르고, 날짜를 누릅니다.
2. 오른쪽 위 **+ 일정**을 누르고 제목·시간을 쓴 뒤 **저장**합니다. 그 날짜 아래에 점이 생깁니다.
3. 마감일이 있는 할 일도 캘린더의 그 날짜에 자동으로 표시됩니다.
4. 위쪽 **월 / 주** 버튼으로 보기 방식을 바꿀 수 있습니다.

### ⑥ 내 취향대로 바꾸기
- 왼쪽 아래 **배경**을 누를 때마다 **자동 → 흰색 → 검은색**으로 바뀝니다.
- 왼쪽 **보기** 메뉴(오늘·할 일·캘린더)는 **마우스로 끌어서 순서를 바꿀 수** 있습니다.
- 두 설정 모두 새로고침해도 유지됩니다.

## 3. 화면별 사용법

| 메뉴 | 하는 일 |
|---|---|
| **오늘** | 오늘 일정·남은 할 일·오늘 완료한 수. 숫자 타일을 누르면 해당 화면으로 이동 |
| **할 일** | "오늘 / 예정 / 완료됨"으로 나뉜 목록. 제목을 누르면 편집 창(왼쪽 내용, 오른쪽 속성과 그래프) |
| **캘린더** | 월간·주간 보기. 날짜를 누르면 그날의 일정·할 일. 일정 창에서 반복·알림 설정 |
| **히스토리** | 진행 중인 할 일의 브랜치를 git 그래프로 보기 |
| **하루 기록** | 날짜별로 완료한 할 일·지나간 일정(그리고 쓴 메모)을 모아 보기 |
| **배경** | 자동 / 흰색 / 검은색 |
| **휴지통** | 지운 항목을 30일 보관, 복구하거나 완전 삭제 |

### 할 일 창에서 할 수 있는 것
- **메모 · 리스트 · 체크리스트**: 아래쪽 **+ 메모 / + 리스트 / + 체크리스트**로 필요한 것만 붙입니다. 칸 오른쪽 위 ✕ 로 뺍니다.
  - 리스트·체크리스트: **Enter**로 새 항목, 빈 항목에서 **Backspace**로 항목 삭제
  - 목록 줄에는 체크리스트 진행률(예: ✓ 2/5)이 보입니다.
- **우선순위**: 높음·보통·낮음 (높음은 제목 앞에 `!!`)
- **반복**: 매일·매주·매월. 반복 할 일을 완료하면 다음 회차가 자동으로 생깁니다.
- **마감일 9시 알림**: 마감일 오전 9시에 알림 (마감일이 있어야 켤 수 있어요)

### 알림 켜는 법
1. **오늘** 화면 위쪽 안내 줄의 **알림 켜기**를 누르고, 브라우저가 물으면 **허용**합니다.
2. 일정은 일정 창의 **알림**에서 (시작할 때 / 10분 전 / 30분 전 / 1시간 전 / 하루 전) 중에 고릅니다.
3. 할 일은 편집 창 오른쪽 위의 **마감일 9시 알림** 스위치를 켭니다.

> 알림은 **앱이 브라우저 탭에 열려 있을 때만** 옵니다. 허용하지 않으면 앱 화면 아래에 안내 메시지로 대신 알려 줍니다.

### 메모는 어디에?
메모 화면은 왼쪽 메뉴에서 뺐지만 기능은 남아 있습니다.
- 일정 창의 **메모 쓰기**를 누르면 그 일정과 연결된 메모가 만들어지고 메모 화면이 열립니다.
- 주소 끝에 `#memo`를 붙여서 열 수도 있습니다. (예: `http://localhost:5001/#memo`)
- 메모 안에서 문장을 드래그해 선택하고 **할 일로 만들기 / 일정으로 만들기**를 누르면, `12/3`, `내일`, `오후 3시` 같은 날짜·시간 표현이 자동으로 채워집니다. (규칙으로 찾는 방식이며, 더 똑똑한 인식은 2단계 AI 기능입니다)

## 4. 히스토리 그래프 읽는 법

### 용어 풀이
| 용어 | 뜻 |
|---|---|
| **main** | 앱 전체의 기준 줄기. 가장 왼쪽 파란 선입니다 |
| **브랜치** | main에서 갈라져 나온 가지. 할 일 하나가 가지 하나입니다 |
| **기록(커밋)** | 할 일에 일어난 일 하나. 추가, 마감일 변경, 체크리스트 진행 등 |

### 그래프에서 보이는 것
| 보이는 것 | 뜻 |
|---|---|
| 파란 세로선 | main 줄기 |
| 색깔 있는 세로선 | 진행 중인 할 일 하나의 브랜치. 할 일마다 색이 다릅니다 |
| 선 위의 점 | 기록 하나 |
| main에서 선이 휘어 갈라지는 곳 | 그 할 일을 **추가한 순간** |
| **맨 위 "지금" 줄** | 진행 중인 모든 가지가 모이는 곳. 칩 하나가 할 일 하나이고 빨간 "지남"은 마감이 지난 일 |
| 한 줄에 칩 여러 개 | 사이에 다른 기록 없이 **연달아 추가한 할 일** 묶음 |
| "진행 중" 표시 | 그 브랜치의 가장 최근 기록 |

### 히스토리 화면 구성
- **숫자 타일**: 진행 중 브랜치 / 진행 중 기록 / 완료해서 정리된 일
- **진행 중인 브랜치 카드**: 지금 열린 할 일을 마감 가까운 순으로 보여줍니다. 누르면 그래프에서 그 위치로 이동해요.
- **그래프**: 위가 최신입니다. 기록을 누르면 오른쪽에 자세히 나옵니다.
- **선택한 기록**: 무엇이 바뀌었는지, 이 할 일의 기록 목록(최신이 위), **할 일 열기** 버튼
- **할 일 창 오른쪽 아래**의 작은 그래프에서 기록을 누르면 히스토리 화면의 그 위치로 이동합니다.

### 할 일에서 한 일 → 히스토리에 남는 것
| 한 일 | 히스토리에서 |
|---|---|
| 할 일 추가 | main에서 새 브랜치가 갈라짐 |
| 마감일·우선순위·반복·알림·제목·메모·리스트·체크리스트 수정 | 그 브랜치에 기록이 쌓임 (예: `마감일 11/30 → 12/1`) |
| 완료 체크 | 그 브랜치와 기록이 **완전히 지워짐** |
| 삭제 (휴지통) | 마찬가지로 지워짐 |
| 완료 취소 / 휴지통에서 복구 | main에서 새 브랜치가 다시 갈라짐 |

## 5. 샘플 데이터

앱을 **처음 열면 샘플 할 일 100개가 자동으로 만들어집니다.** (버튼을 누를 필요 없음)
- 자소서·면접·공부·프로젝트·회고·네트워킹·부트캠프·일상·독서·포트폴리오 10가지 주제
- 최근 6주 동안 추가·수정·완료한 것처럼 히스토리도 함께 만들어져, 그래프를 바로 볼 수 있습니다.
- 약 90개는 완료(히스토리에서는 정리됨), 6개는 진행 중, 4개는 휴지통에 있습니다.
- 일부에는 체크리스트·메모·리스트가 들어 있습니다.

### 샘플 다시 만들기 / 데이터 전부 지우기
> ⚠️ 이 브라우저에 저장된 **모든 할 일·일정·메모가 지워집니다.** 직접 만든 데이터가 있다면 신중하게 하세요.

1. 앱이 열려 있는 탭에서 개발자 도구를 엽니다. (Mac: `Cmd + Option + J`, Windows: `Ctrl + Shift + J`)
2. **Console** 탭에 아래 한 줄을 붙여 넣고 Enter를 누릅니다. 붙여넣기가 막혀 있다고 하면 `allow pasting`을 먼저 입력하고 Enter를 누르세요.
   ```js
   localStorage.removeItem('harunote-data-v1'); location.reload();
   ```
3. 페이지가 새로고침되면서 새 샘플 100개가 만들어집니다.

## 6. 고쳐서 올리기 (GitHub → 자동 배포)

코드를 고치면 GitHub에 올리는 것만으로 **사이트가 자동으로 업데이트**됩니다.

```
내 컴퓨터에서 고침 → GitHub에 올림(push) → Vercel이 자동 배포 → 약 20초 뒤 사이트에 반영
```

1. 코드를 고치고, 로컬 서버(`localhost:5001`)에서 새로고침해 확인합니다.
2. 터미널에서 이 폴더로 이동해 아래 세 줄을 차례로 실행합니다. (Claude Code에서는 "GitHub에 올려줘"라고 말해도 됩니다)
   ```bash
   git add -A
   git commit -m "무엇을 바꿨는지 한 줄로"
   git push
   ```
   - `git add -A`: 바뀐 파일을 올릴 목록에 담기
   - `git commit -m "..."`: 지금 상태를 이름 붙여 저장하기
   - `git push`: GitHub에 올리기
3. 약 20초 뒤 사이트에 반영됩니다. **이미 열려 있던 탭은** `Cmd + Shift + R`(Windows: `Ctrl + Shift + R`)로 새로고침해야 새 버전이 보입니다.

> 🔒 `.env` 파일과 `.vercel` 폴더는 GitHub와 사이트에 올라가지 않도록 막아 두었습니다. **API 키·비밀번호는 코드나 문서에 직접 적지 마세요.**

> 참고: 자동 배포를 거치지 않고 직접 배포하려면 `vercel deploy --prod`를 쓸 수 있습니다. (처음 한 번 `vercel login`이 필요합니다. 평소에는 위 방법만으로 충분합니다.)

## 8. 알아 둘 한계

- **데이터는 그 브라우저에만 저장됩니다.** 다른 기기·브라우저와 동기화되지 않고, 브라우저의 사이트 데이터를 지우면 함께 사라집니다. `localhost:5001`과 배포 사이트의 데이터도 서로 따로입니다.
- **알림은 앱이 브라우저에 열려 있을 때만 옵니다.**
- **반복 일정을 고치면 모든 회차가 함께 바뀝니다.** 특정 회차만 바꾸는 기능은 없습니다.
- **히스토리에는 진행 중인 할 일만 남습니다.** 완료·삭제한 할 일의 기록은 지워지고, 일정·메모는 기록하지 않습니다.
- 배포 후 **이미 열려 있던 탭**은 새로고침해야 새 버전이 보입니다.

## 11. 다음 단계

PRD의 **2단계(AI 기능)**를 계획하고 있습니다.
- 할 일 자동 제안: 문장 속 날짜·시간을 찾아 할 일·일정 만들기를 제안
- 체크리스트 자동 만들기: 큰 할 일을 작은 단계로 쪼개기
- 주간 회고 요약: 한 주 동안 완료한 일과 히스토리 요약
- 마감 위험 알림: 진행 중인 브랜치의 기록과 마감일을 보고 늦어질 일을 알려주기

AI 기능에는 API 키(외부 AI 서비스를 쓰기 위한 비밀 열쇠)가 필요합니다. API 키는 코드나 문서에 직접 적지 마세요.
